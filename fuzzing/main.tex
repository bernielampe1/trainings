\begin{enumerate}

    \item Most important question is "When is using fuzzing appropriate/productive?" and "If fuzzing is appropriate, what type of fuzzing should be used?"
	\item Fuzzing has low false positives.
    \item Fuzzing has hard time getting past encryption, hashing or compression algorithms. Usually patched out or fuzzing afterwards.

	\item Fuzzing results in an unminimized input file that triggers a bug.
	\item Must triage outcomes (crashes, hangs) first.
	\item Root causing can be hard. Minimize input first by bi-secting input.
\end{enumerate}

\section*{Fuzzing Theory}
\begin{enumerate}
	\item Dump fuzzing, black box. No knowledge. Low penetration.
	\item Smart fuzzing, white box. Complete re-implement parser. Max penetration.
    \item Need a mix of both to hit unknown code path in unexpected ways.

    \item Fuzzing can be seen as following compiler design in reverse. (Lexical analysis, syntax analysis, semantic analysis, code generator, optimizer, assembly generation.)
	\item Fuzzing as a search general problem.
	\item Fuzzing as a maze analogy.
	\item Fuzzing as a directed search problem (A*).
\end{enumerate}
